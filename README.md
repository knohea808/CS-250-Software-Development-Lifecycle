# CS 250: Software Development Lifecycle

## Sprint Review and Retrospective

This repository contains my Sprint Review and Retrospective from CS 250 at Southern New Hampshire University. Throughout this course, I learned about the software development lifecycle and how Agile and Scrum can help teams develop software while adapting to changes. The SNHU Travel project helped me understand how different Scrum roles work together and why communication is important during development.

### How do I interpret user needs and implement them into a program? How does creating user stories help with this?

I interpret user needs by understanding what the user wants to accomplish and how the program can help them. User stories make this easier because they describe features from the user's perspective. They help developers focus on what is important to the user rather than just the technical side of the program. They also make it easier to break larger requirements into smaller tasks.

### How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

I approach developing programs by breaking larger problems into smaller steps and working on them one at a time. I like how Agile allows developers to make improvements throughout the development process instead of waiting until the end. In the future, I would like to use sprint planning, regular communication, and retrospectives to stay organized and improve my work.

### What does it mean to be a good team member in software development?

Being a good team member means communicating clearly, being dependable, and being willing to help others when needed. Software development involves different people working toward the same goal, so teamwork is important. I think being open to feedback and adapting to changes are also important because problems can come up at any point during development.
